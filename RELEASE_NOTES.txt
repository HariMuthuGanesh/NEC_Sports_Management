Role workflows and sports reports

Source branch: master

Deployment
1. Configure backend environment values for the target database, JWT_SECRET,
   COOKIE_SECRET, CSRF_SECRET, allowed frontend origins, and mail as needed.
   Configure VITE_API_URL before building the frontend.
2. Install locked dependencies with npm ci in backend and frontend.
3. Back up the target database, then run npm run migrate in backend.
   Migrations 022-028 are required; migration 027 disables the retired
   CollegeTeamOnly admin login and invalidates its sessions. Migration 028
   links gallery uploads to events while preserving existing uploads.
4. Run npm run build in frontend and publish its dist directory.
   Start backend with npm start using the production environment.

Full admins use College Teams from their existing session. A second full
admin can be created with npm run create:account. Preset provisioning also
accepts SECOND_ADMIN_USERNAME, SECOND_ADMIN_EMAIL, SECOND_ADMIN_PASSWORD.
Do not run demo seeds against production or store passwords in source files.

Roles
- Admin: sports and teams, accounts, security audits, and OD approvals.
- Sports President: sports and teams across departments; no user management,
  security audit, or OD approval.
- Coordinator: own department teams, captain assignments, attendance.
- Captain: active department-and-sport assignments, squads, attendance.
- Score Updater: view schedules; update only ongoing matches/competitions.
- Player: own team memberships, match history, event results, OD status.
- Public: the home page keeps the sidebar Login menu item. Duplicate header,
  hero and bottom-left sign-in buttons are hidden on the home page only.

Sports workflow
Create sports and their categories in Sports Catalog. Create a tournament
and its events. Team sports use approved-team fixtures. Event Competitions
supports category heats/finals, individual entrants, and same-department
relay squads with an exact roster size. Time sorts lowest first; distance
and points sort highest first. Equal results share a rank. DNS, DNF, and DQ
are recorded without a rank. All results must be entered before completion.
Officials enter the measured result; apparatus-specific attempt rules and
automatic heat qualification are not automated.

Reports
Institutional Reports now generates a college sports activity report for an
inclusive date range. It includes overlapping events, team fixtures, ranked
competitions, scores, results and recorded participation. Activities retain
their completed, ongoing, scheduled or postponed status. Distinct athletes
come from attendance and competition results, not roster membership.
Each event includes its linked gallery photos, even if uploaded later.
Select an Event on new uploads or existing photos in Gallery Manager.
Unassigned photos are excluded until linked. No caption matching is guessed.
Print and paginated PDF exports include the event summaries and optional
photos. Coordinator reports restrict athlete details to their department.
Certificates remain available in their separate tab.

Verification
Backend npm test creates and removes its own isolated MySQL database.
It checks migrations, real API operations, roles, attendance, notifications,
athletics, reports, score status restrictions, and logout revocation.
Browser release-workflows tests use API fixtures to verify frontend behavior.
Activity report tests cover date validation, actual participation, rankings,
department scope, event photos, empty/error states, PDF download and mobile
layout. Run node --test backend/scripts/activityReport.test.js and, from
frontend, npx playwright test e2e/activity-report.spec.js --project=chromium.
Production database migrations and hosting deployment are separate steps.
